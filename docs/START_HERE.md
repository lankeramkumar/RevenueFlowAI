# Give this package to Claude Code

This package specifies RevenueFlow AI: a CSV-based Order-to-Cash application with a chatbot, supervisor, three specialist agents, and synthetic data generated by Claude Code.

## Files

| File | Purpose |
|---|---|
| intent.md | Product scope, CSV contracts, financial rules, UI, security, and acceptance criteria |
| agent_architecture.md | Supervisor, Order/AR/Cash specialists, routing, communication contracts, budgets, failures, and chat context |
| synthetic_data_requirements.md | Reproducible generator, demo/load profiles, fixed scenarios, and expected results |
| claude_build_prompt.md | The full instruction to paste into Claude Code |

## Start

1. Create a project folder, or use the repository where you want this application built.
2. Copy these four Markdown files into the project root. If you have older versions of intent.md or claude_build_prompt.md, replace them with these updated versions.
3. Open Claude Code in that folder. Paste the instruction section from claude_build_prompt.md (everything after its introductory divider).
4. Claude should inspect the repository, implement the application, generate synthetic data, and run verification. You do not need to supply Oracle credentials or CSV files.
5. Supply an Anthropic API key only through the implemented server-side environment configuration when you want live AI. Credential-free demo mode remains available. Never paste secrets into these Markdown files or commit them.

You can also start with this shorter instruction:

```text
Read @intent.md, @agent_architecture.md, @synthetic_data_requirements.md,
and @claude_build_prompt.md. Execute the full build instructions in
claude_build_prompt.md. Implement and verify the CSV-first application,
chatbot, supervisor plus Order/AR/Cash Application specialists, and
reproducible synthetic data. Continue through testing and the acceptance
report; do not stop at a plan or mocked UI.
```

## Architecture scope

The agreed first release uses supervisor-to-specialist communication inside one application. A2A protocol services for independently deployed agents are future scope, with a migration design required. This package does not promise an A2A-compliant implementation in the first release.

The files are requirements for Claude to implement, not a prebuilt application or ready-to-run CSV generator. Production readiness must be supported by actual checks, environment configuration, and operational validation.
